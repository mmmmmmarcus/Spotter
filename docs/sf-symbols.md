# SF Symbols

Search `SF Symbols` in the launcher, or type `sf heart`, `sf symbols heart` or `sfsymbols heart` to
open the shared palette with that query. Settings → Shortcuts can assign the SF Symbols action a
shortcut; none is claimed by default.

The feature requires Apple's **SF Symbols 27 or later**. `NSWorkspace` locates the installed app by
`com.apple.SFSymbols`, then Spotter checks `Contents/Executables/sfsymbols`. Missing tools produce an
update instruction in the palette and Settings. Apple distributes the update through System Settings
→ Software Update and its [SF Symbols download page](https://developer.apple.com/sf-symbols/).
Spotter does not install or update that app automatically.

## Interaction

The palette keeps its existing search field, footer, selection and Actions menu. `SFSymbolBrowserView`
uses `PluginPaletteList` on the left and a persistent large preview on the right. The canvas context
carries the palette's `ScrollIntent`, so keyboard navigation uses the same scroll behavior as other
lists. Preview metadata includes the CLI's code point and minimum macOS version, when available.
AppKit renders previews using the running system's symbols; unavailable images explain that a newer
macOS is needed rather than drawing a substitute.

- Return / click copies the exact symbol name.
- Command-Return copies a transparent monochrome PNG generated by Apple's CLI.
- Actions also copies SwiftUI `Image(systemName:)` code or the editable SVG **template** returned by
  Apple's export command, and can open the SF Symbols app.

PNG output uses point size 128 and image scale 2. SVG is Apple's multi-variant design template, not a
flattened single-glyph SVG. Copying writes the system clipboard only on explicit activation. Text and
PNG copies participate in the ordinary clipboard history. Export errors log through `AppLog` and show
a failure HUD without replacing the clipboard with an empty result.

## Ownership and execution

`AppCore` solely owns `SFSymbolStore`; `SFSymbolPlugin` registers one palette screen, command, bindable
action and Settings pane. There is no new window, singleton, persistence, consent toggle or runtime
plugin loading. The feature creates no network requests or background polling.

`SFSymbolStore` debounces the palette query for 120 ms. `SFSymbolCLI` invokes the installed executable
directly with `Process`, never a shell. Search uses `search --json --limit 150 -- <query>`; the final
query is one literal argument, including whitespace or leading dashes. Empty search asks the CLI for
its default catalog order. The result limit is labelled when reached; narrowing the query searches
the full catalog. Search ranking, aliases and keyword handling remain Apple's implementation.

Searches expire after 10 seconds; exports after 30. Cancellation kills only the owned CLI process,
and obsolete results cannot publish after the query changes or the screen closes. Blocking process
waits execute on a dispatch worker. Separate temporary stdout/stderr files avoid pipe backpressure;
reads are bounded, exit status and stderr are checked, and all handles and temporary files are
cleaned on success, cancellation, timeout and failure. Temporary directories are bundle-identifier
scoped and private. Exports use unique temporary destinations and never overwrite user files.

`SFSymbolCatalog` is pure Foundation: bounded JSON decoding, safe names, SwiftUI code and launcher
prefix parsing. `SFSymbolCLI` stays Foundation + Darwin; `SFSymbolStore` stays Foundation + Combine.
`Tools/sf-symbols-test.swift` covers parsing, argument isolation, query cancellation, process failures,
timeout, missing CLI and clipboard-ready export data. When the actual CLI is installed it also searches
and exports PNG/SVG in temporary files, without opening the UI or writing the real clipboard.
