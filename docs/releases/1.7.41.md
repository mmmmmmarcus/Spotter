## Fixes

- **The Hyper Key no longer dies partway through a session.** Hyper would stop working — a combination like ✦ T doing nothing, or registering as a plain modifier — and stay broken until you changed the Hyper Key setting or logged out. Confusingly, holding the key on its own still looked correct, which made it seem like the shortcut was at fault rather than the key.

  The cause: Spotter worked out whether you had pressed or released the Hyper key by alternating — treat the first event as a press, the next as a release, and so on. Nothing ever checked that against reality. macOS briefly switches a keyboard listener off when an app is busy for a moment, and if that happened while you were holding the Hyper key, Spotter lost its place: from then on every press was read as a release and every release as a press, for the rest of the session.

  Spotter now reads press and release from the key event itself, which carries that fact directly. It cannot drift, and it re-synchronises on the very next keystroke if the system interrupts it. Quick Press, the Shift option and Caps Lock as the Hyper key all behave exactly as before.

- **Diagnostics can now see the Hyper Key.** This subsystem previously recorded nothing at all, which is why the problem above was invisible for so long. Settings → Diagnostics now shows when the key listener starts, when macOS interrupts it, when the Accessibility permission is missing or has been revoked, and when Spotter has had to re-establish the key's state. It records only these events — never which keys you press.

Updating from 1.7.37 or later installs normally through Check for Updates. If you are still on 1.7.36 or earlier, install this version from the DMG once and grant Accessibility, Input Monitoring, Screen Recording and Full Disk Access again, as described in the 1.7.37 notes.
